**Готово, если:**
* Структура соответствует рекомендации и папки называются так.

### Задача 2 — `GDD.md`: несколько разделов “для примера” (не полный GDD)

**Цель:** зафиксировать стартовые гипотезы, чтобы на следующем занятии было что уточнять. 

**Сделать в `GDD.md`:**
Добавить **минимум 3–4 раздела**, каждый по **5–10 строк** (можно списками):
* **One-liner / Elevator pitch**
* **Core loop (черновик)**
* **Pillars (3 опоры проекта)**
* **Контент/ассеты (черновик: что придётся сделать)**

**Готово, если:**

### Задача 3 — `README.md`: ориентир проекта (черновик)

**Цель:** чтобы преподаватель открывал репо и сразу понимал “что за проект”. 

**Заполнить в `README.md` (4 строки + список):**
* **Жанр**
* **USP (1–2 предложения)**
* **ЦА**
* **Платформы**
* Ссылка/указание: где смотреть главное (`GDD.md`, `logs/gdd-log.md`, `images/selected/`)

**Готово, если:**
* README читается за 30 секунд и содержит навигацию.

### Задача 4 — `logs/gdd-log.md`: минимум 3 записи журнала (промпты/решения)

**Цель:** закрепить обязательную дисциплину логирования процессов в Obsidian. 

**Создать файл:** `logs/gdd-log.md`

**Сделать:** минимум **3 записи** в формате:
* **Подготовка** (что хотели получить и критерии)
* **Промпт**
* **Результат** (кратко)
* **Вывод** (что принимаем/отбрасываем и почему)

**Подсказка по темам 3 записей (достаточно текстовых задач):**
1. Название + one-liner (3 варианта → выбор 1)
2. Core loop (2–3 версии → выбор/синтез)
3. 3 pillars (варианты → финальная формулировка)

**Готово, если:**
* В каждой записи есть **вывод** (без этого запись считается незавершённой).
