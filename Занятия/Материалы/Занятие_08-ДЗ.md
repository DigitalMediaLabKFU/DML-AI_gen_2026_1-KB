## Контекст

Это домашнее задание продолжает занятие:

**Занятие 8 — ComfyUI 4: ControlNet (pose/depth/canny) + демо FaceID**

На практике достаточно использовать **Depth** и **Canny** через стандартные шаблоны ComfyUI, доступные в **cloud.comfy.org**.  
`Pose`, `OpenPose`, `FaceID`, дополнительные LoRA и нестандартные ноды — **по желанию и только если доступны**.

Главная цель — не “нагенерить много картинок”, а подготовить управляемые основы для будущих скрингенов проекта.

---

## Что нужно сделать

### Задача 1 — Подготовить 2 сцены через Depth и / или Canny

**Цель:** получить управляемые кадры, которые можно развивать в будущие скрингены.

Сделать минимум **2 результата**:

1. **1 сцена через Depth**
   - акцент на глубине, перспективе, переднем / среднем / дальнем плане;
   - подходит для коридора, арены, помещения, улицы, уровня, сцены с целью в глубине.

2. **1 сцена через Canny**
   - акцент на контурах, силуэтах, форме сцены или объекта;
   - подходит для скетча уровня, арены, платформы, здания, пропа, архитектурной формы.

Можно сделать 2 Depth или 2 Canny, если для вашего проекта один подход явно полезнее. Но в логе нужно объяснить выбор.

**Инструмент:**
- основной вариант: `cloud.comfy.org`;
- использовать стандартные шаблоны ComfyUI для Depth / Canny;
- не использовать редкие кастомные ноды как обязательную часть задания.

### Задача 2 — Сохранить workflow

Сохранить рабочий workflow:


Если использовали два отдельных шаблона, допустимо сохранить два файла:


Рекомендуемые имена:

```text

outputs/selected/08-canny-scene-02.png
```

Если в вашем проекте используется `images/selected/`, сохраняйте туда и не дублируйте папки.

**Минимум для сдачи:**

* 2 selected output;
* один из них через Depth;
* один через Canny или второй Depth/Canny с объяснением выбора.

**Не нужно:**

* складывать в selected все черновики;
* коммитить десятки случайных генераций;
* загружать тяжёлые raw-папки.

## Что считается хорошей работой

Хорошая работа — это не максимальное количество генераций.

Хорошая работа показывает:

* студент понимает, зачем использует Depth или Canny;
* сцены связаны с будущими скрингенами;
* selected output отобраны осознанно;
* workflow сохранён;
* в логе есть выводы;
* GDD / shot-list стали конкретнее после выполнения задания.

---

## Типовые ошибки

* Использовать ControlNet без понимания, что именно контролируется.
* Делать красивую сцену, которая не связана с проектом.
* Положить в selected слишком много черновиков.
* Не сохранить workflow.
* Не записать input и выводы в `workflow-notes.md`.
* Взять слишком шумный input для Canny.
* Использовать Depth на плоской сцене без перспективы.
* Пытаться собрать сложный граф с недоступными нодами вместо стандартного шаблона.
