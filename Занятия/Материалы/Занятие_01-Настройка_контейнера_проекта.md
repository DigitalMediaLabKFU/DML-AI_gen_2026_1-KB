
Ниже — **пошаговая инструкция** по настройке “контейнера проекта”: **Obsidian vault (локальная база знаний)**, который **версионируется Git** и синхронизируется через **GitHub**. В рамках курса это обязательная основа: **все решения и процессы должны логироваться в Obsidian** (“не задокументировано — значит не сделано”).  

---

## 1) Что такое Obsidian и Git и зачем они нужны

**Obsidian**

* Локальная база знаний (папка‑vault) с заметками в Markdown.
* Используется как основная среда проекта: GDD, логи решений, ссылки между страницами, навигация. 

**Git + GitHub**

* Git — система контроля версий: фиксирует изменения (коммиты), позволяет откатываться и видеть историю.
* GitHub — удалённое хранилище репозитория: удобно сдавать, проверять и синхронизировать между устройствами.
* Для курса критично: вы сдаёте **не только результат**, но и **процесс**, поэтому история и логи обязательны.

## 2) Рекомендации по расположению Obsidian vault (важно)

**Требования к папке vault:**
1. **Не размещать в OneDrive/Google Drive/Dropbox и т.п.**
   Причина: двойная синхронизация (облако + Git) часто даёт конфликты и “битые” состояния.
2. Создать отдельную и простую структуру каталогов, например:
   **`D:/University/Obsidian/`**
   Внутри будут ваши vault‑проекты.
3. **Избегать кириллицы и спецсимволов в пути** (и по возможности пробелов).
   Причина: меньше проблем с Git/плагинами/терминалом и переносимостью.

**Пример целевого пути vault:**
`D:/University/Obsidian/GenAIGDIvanIvanov/`

## 3) Создание репозитория в GitHub

1. GitHub → **New repository**.
2. **Название репозитория**:
   `GenAIGD_` + `ИмяФамилия` на латинице, без пробелов.
   Пример: `GenAIGD_IvanIvanov`
   (Префикс требуется стандартом курса.) 
3. Можно оставить галочку **“Add a README file”**.
   **Рекомендуется оставить**: так репозиторий будет **не пустым**, появится ветка (обычно `main`), и дальнейшие clone/push проходят проще.

## 4) Создание PAT в GitHub и клонирование через Git CMD по ссылке с токеном

### 4.1. Создать PAT (Personal Access Token)

Путь в GitHub (официально):
Profile → **Settings** → **Developer settings** → **Personal access tokens** → (Fine‑grained tokens / Tokens classic) → **Generate**. ([GitHub Docs][1])

Рекомендации по PAT (минимально разумно):

* ставьте **expiration** (срок действия)
* выдавайте доступ **только к нужному репозиторию** (если используете fine‑grained)
* права должны позволять **запись в репозиторий** (push)

> PAT — это пароль. Не отправляйте его в чат/скриншоты/репозиторий. Если утёк — немедленно удалите/перевыпустите токен.

### 4.2. Правильный формат URL для remote с “вшитой” авторизацией

Используйте **такой** формат (исправленный):

```text
https://<username>:<PAT>@github.com/<owner>/<repo>.git
```

Где:

* `<username>` — ваш логин GitHub
* `<PAT>` — токен
* `<owner>` — владелец (обычно ваш username)
* `<repo>` — имя репозитория

### 4.3. Клонирование репозитория в локальную папку (Git CMD)

1. Откройте **Git CMD**.
2. Перейдите в базовую папку:

```bat
cd /d D:/University/Obsidian
```

3. Клонируйте репозиторий:

```bat
git clone https://<username>:<PAT>@github.com/<owner>/<repo>.git
```

Проверка:

```bat
cd <repo>
git status
git remote -v
```

## 5) Создание Obsidian vault в выбранной папке (и что делать с “существующей папкой”)

### Вариант А (рекомендуемый, без лишних переносов): открыть существующую папку как vault

Obsidian умеет использовать **существующую папку** как vault через **Open folder as vault**. ([Obsidian Help][2])

Шаги:

1. Obsidian → переключатель vault (внизу слева) → **Manage vaults…**
2. **Open folder as vault** → **Open**
3. Выберите папку клонированного репозитория, например:
   `D:/University/Obsidian/GenAIGD_IvanIvanov/`
4. Vault готов: теперь это одновременно **Obsidian‑vault** и **Git‑repo**.

### Вариант B (если вы делаете строго через “Create new vault” и Obsidian требует новую папку)

Контекст: в режиме **Create new vault** Obsidian создаёт **новую** папку; существующую выбрать может быть неудобно. Тогда делайте так:

1. У вас есть папка репозитория после clone:
   `D:/University/Obsidian/GenAIGD_IvanIvanov/`
2. **Переименуйте** её, например в:
   `GenAIGD_IvanIvanov_repo_tmp`
3. В Obsidian выберите **Create new vault** и создайте новый vault с нужным именем:
   `D:/University/Obsidian/GenAIGD_IvanIvanov/`
4. **Перенесите в новый vault всё содержимое** из `*_repo_tmp`, **включая скрытую папку `.git`** (иначе Git “пропадёт”).

   * В проводнике Windows включите отображение скрытых файлов, чтобы увидеть `.git`.

## 6) Примеры блоков `.gitignore` (системное + Obsidian)

Создайте файл `.gitignore` в корне vault (рядом с README).

### Блок 1 — системные файлы (Windows/macOS)

```gitignore
# OS junk
.DS_Store
Thumbs.db
Desktop.ini
```

### Блок 2 — Obsidian: рабочие пространства и кэш (частые конфликты, не нужны для проверки)

```gitignore
# Obsidian (machine-specific)
.obsidian/workspace.json
.obsidian/workspace-mobile.json
.obsidian/cache/
.obsidian/.trash/
```

### Блок 3 — тяжёлые/временные данные (под ваш проект)

```gitignore
# Temporary / heavy artifacts (пример)
outputs/raw/
media/raw/
*.mp4
*.mov
*.psd
```

Контекст: `.obsidian/` хранит настройки и плагины. Полностью игнорировать `.obsidian/` можно, но тогда настройки не будут переноситься. Практичный минимум — игнорировать workspace/cache, чтобы не ловить конфликтов.

## 7) Установка плагина Git в Obsidian (Obsidian Git)

1. Obsidian → **Settings**
2. **Community plugins**
	* выключить Restricted mode (если включён)
3. **Browse**
4. Найти **Git** → **Install** → **Enable**
5. Открыть **Options** плагина и проверить базовые параметры (путь к git обычно не нужен, если Git установлен корректно)

Функционально плагин даёт Source Control‑окно: stage/commit/push/pull и “commit-and-sync”. ([Obsidian][3])

## 8) Проверка commit и push через GUI плагина (и что делать в особых случаях)

### 8.1. Нормальный случай (репозиторий не пустой, есть README/ветка)

1. В Obsidian откройте **Command Palette** (`Ctrl+P`)
2. Команда: **Open source control view** (или аналогичная от Git‑плагина) ([Obsidian][3])
3. Дальше по кнопкам в интерфейсе:
	* **Stage** (или Stage All)
	* **Commit** (введите сообщение или оставьте шаблон по умолчанию)
	* **Push** (или **Commit-and-sync**) ([Obsidian][3])

Плагин покажет уведомление об успехе/ошибке (обычно в правом верхнем углу).

Проверка: откройте GitHub в браузере → вкладка commits → убедитесь, что коммит появился.

### 8.2. Если репозиторий оказался “пустым” (без веток/коммитов)

Контекст:
* пустой репозиторий может ломать привычный push из GUI: коммит создать можно, а push потребует первичной настройки ветки/upstream.

Решение (через Git CMD в папке vault):

```bat
git status
git add -A
git commit -m "init vault"
git branch -M main
git push -u origin main
```

После этого возвращайтесь в Obsidian Git — дальше push/pull обычно работают штатно.

## 9) Ограничения по размеру Git/GitHub и рекомендация по медиа

Что важно учитывать:

* GitHub рекомендует держать репозитории **маленькими**, **идеально < 1 GB**, и **< 5 GB** — настоятельно рекомендуется, иначе начинаются проблемы с производительностью и возможны запросы “починить размер”. ([GitHub Docs][4])
* Ограничения GitHub по объектам и пушам:
	* **один файл**: рекомендовано значительно меньше, но есть **жёсткое ограничение 100 MB** на объект ([GitHub Docs][5])
	* **размер одного push**: ограничение **2 GB** ([GitHub Docs][5])

Практическое правило для учебного проекта:
* держите репозиторий в диапазоне **до ~1–2 GB** (организационный потолок),
* **не складируйте** в Git “сырые” видео/архивы/десятки тяжёлых ассетов,
* храните тяжёлое локально (например, `media/raw/`, `outputs/raw/`) и исключайте через `.gitignore`, а в репозиторий кладите только отобранное и проверяемое.

### Финальная проверка “контейнер настроен”

* Vault открывается в Obsidian и редактируется.
* В корне vault есть `.git/` (репозиторий живой).
* Obsidian Git показывает изменения, делает commit и push. ([Obsidian][3])
* На GitHub видны коммиты.
