
## Кратко: зачем единые имена и структура

* **Скорость проверки и навигации.** Преподаватель и вы всегда знаете, где что лежит и как это открыть за 30–60 секунд.
* **Сортировка “по имени” становится смысловой.** Числовые и датированные префиксы дают правильный порядок без ручной сортировки.
* **Дисциплина процесса.** Все шаги работы фиксируются в `logs/` (логирование обязательно: Подготовка → промпт → результат → (правки) → ... → промпт → результат → вывод).

---

# 1) Общие правила именования файлов (универсальные)

**Жёсткие правила**

1. **Только латиница, цифры, дефис `-`, подчёркивание `_` (по минимуму).**
   Избегаем кириллицы и спецсимволов: меньше проблем с Git, терминалом и переносимостью.
2. **Разделитель слов — дефис**: `core-loop`, `combat-system`, `sdxl-txt2img`.
3. **Одна логика на весь vault**: одинаковые категории и порядок слов.
4. **Имя файла должно быть “самодостаточным”**: по названию понятно, что это и к чему относится.

**Рекомендации**

* Старайтесь держать названия **короткими (3–6 слов)**.
* Для серий используйте **единый формат**: `01-...`, `02-...` и т.д. (одинаковая длина префикса).

---

# 2) Префиксы и когда какой использовать

## 2.1. Числовые префиксы: `00-`, `01-`, `02-`

**Назначение:** принудительный порядок при сортировке по имени (в проводнике, Git, списках файлов).

**Правило:**
* Используйте **одинаковую длину** (например, всегда 2 цифры).
* Применяйте в наборах, где важен порядок чтения/показа.

**Примеры**
* `00-overview.md`
* `01-concept.md`
* `02-core-loop.md`

> Рекомендация: `00-` — “входные/обзорные”, `01-02-...` — основные материалы по логике чтения. Если у вас другой порядок — главное, чтобы он был единым.

---

## 2.2. Тип + номер: `w00-`, `w01-`, `w02-` (пример: `w` = workflow)

**Назначение:** тот же порядок сортировки + явная связь с типом данных.

**Правило:**
* Одна буква (или короткий код) + **двузначный номер** + описание.
* Типовой код держите единым: `w` только для workflow.

**Примеры**
* `w01-sdxl-txt2img.json`
* `w02-sdxl-img2img-inpaint.json`

> Если появятся другие типы, используйте аналогичный принцип (например, `r01-...` для reference-пакетов), но **не плодите типы без необходимости**.

---

## 2.3. Дата: `YYYY-MM-DD-`

**Назначение:** хронологический порядок при сортировке по имени.

**Когда использовать**

* Для **отчётов/срезов** (midterm/final), чтобы было видно “какая версия сдавалась когда”.
* Для **дневников/сессий** (если ведёте отдельные записи по дням).

**Примеры**

* `reports/2026-02-11-midterm.md`
* `reports/2026-03-01-final.md`

**Правило выбора даты**

* Для **снимков/сдач**: дата = **дата фиксации** (когда вы сдаёте/подводите итог).
* Для **живых документов** (например, `GDD.md`): дату в имени обычно **не используем**, иначе появится хаос из “версий по датам”.

# 3) Поддиректории и что в них хранить (строго по назначению)

## `logs/` — журнал работы и запросов (обязательно)

**Что хранить**
* Все запросы, заметки процесса, решения и выводы.
* Логи важнее “красивых результатов”: без логов работа считается не выполненной по процессу.

**Типовые файлы**
* `logs/gdd-log.md` — решения по GDD: что поменяли и почему.
* `logs/workflow-notes.md` — заметки по ComfyUI workflow: настройки, версии, проблемы, выводы.

**Мини-правило записи**
* **Подготовка → промпт → результат → (правки) → ... → промпт → результат → вывод**

---

## `reports/` — итоговые обобщения

**Что хранить**
* Срезы и выводы по этапам (midterm/final), кратко и проверяемо.

**Правило именования**
* Всегда с датой: `YYYY-MM-DD-midterm.md`, `YYYY-MM-DD-final.md`

---

## `workflows/` — финальные конфиги ComfyUI

**Что хранить**
* Только **финальные** или “рабочие” workflow, которые вы реально используете/сдаёте.
* Порядок — по `w01-`, `w02-`…

**Правило именования**
* `wNN-<model>-<task>.json`
  Пример: `w01-sdxl-txt2img.json`

---

## `images/selected/` — избранные изображения для проверки

**Что хранить**
* Только то, что вы готовы показывать и защищать.
* Набор должен быть компактным и “по делу”.

**Именование**
* Числовой префикс + категория + номер:
  `01-character-1.png`, `02-location-1.png`

---

## `images/raw/` — сырые изображения (опционально)

**Что хранить**
* Черновые/массовые результаты, которые не обязаны к проверке.

**Рекомендация**
* Часто имеет смысл **не версионировать** (или хранить очень ограниченно), чтобы не раздувать репозиторий.

---

## `media/` — аудио/видео/3D

**Что хранить**
* Результаты генерации и ассеты по медиа.

**Рекомендация**
* Держите структуру по типам: `audio/`, `video/`, `3d/`
* Тяжёлые файлы — по возможности вне Git (или строго ограниченно).

---

# 4) Рекомендуемая структура vault (эталон)

```text
/vault/                      ← Obsidian vault — корень базы знаний
  .gitignore
  GDD.md
  README.md
  .git/
  .obsidian/
  logs/
    gdd-log.md
    workflow-notes.md
  reports/
    YYYY-MM-DD-midterm.md
    YYYY-MM-DD-final.md
  workflows/
    w01-sdxl-txt2img.json
    w02-sdxl-img2img-inpaint.json
  images/
    selected/
      01-character-1.png
      02-location-1.png
      ...
    (optional) raw/          ← личное, не обязано к проверке
  media/
    audio/
    video/
    3d/
```

**Контекст (почему так)**

* В корне лежат только “точки входа”: `README.md`, `GDD.md`, `.gitignore` — минимум шума.
* `logs/` отделён от `reports/`: **процесс** отдельно от **итога**.
* `workflows/` и `images/selected/` — это то, что чаще всего открывают при проверке.

# 5) Практические шаблоны имен (копипаст-правила)

## Для документов внутри `reports/`

* `2026-02-11-midterm.md`
* `2026-03-10-final.md`

## Для workflow внутри `workflows/`

* `w01-sdxl-txt2img.json`
* `w02-sdxl-img2img-inpaint.json`
* (если нужна версия) `w02-sdxl-img2img-inpaint-v02.json`

## Для избранных изображений `images/selected/`

* `01-character-1.png`
* `02-location-1.png`
* `03-prop-1.png`

# 6) Мини-чек-лист “правильно ли оформлен vault”

* [ ] Путь к vault без кириллицы/спецсимволов
* [ ] В корне нет случайных разрозненных файлов (кроме ключевых)
* [ ] Есть `logs/` и в нём реально ведутся записи
* [ ] `reports/` содержит датированные срезы
* [ ] `workflows/` содержит только рабочие `wNN-...json`
* [ ] `images/selected/` содержит только отобранное, имена упорядочены `01-`, `02-`…
