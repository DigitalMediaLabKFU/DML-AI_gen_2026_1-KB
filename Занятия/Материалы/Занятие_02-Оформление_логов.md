
## Почему логи важны

- **"Не задокументировано — значит не сделано"**
- Лог показывает процесс: попытки → отбор → выводы
- Преподаватель проверяет качество работы по логу
- Ты сам(а) сможешь вернуться к решению через месяц и понять, почему выбрал тот или иной вариант

---

## Формат записи в логе

Каждый шаг начинается с заголовка второго уровня, описывающего суть шага, например:

```
## Шаг N. Название шага
```

Внутри — пары блоков (callout):

**Блок запроса пользователя:**

```
> [!question] User {{date}}
> 
> ```
> Текст вашего запроса
> ```

```

**Блок ответа модели:**

```
> [!todo] Answer with **Название модели** {{date}}
>
> Текст ответа модели (или ключевые фрагменты)
```

После блоков — 2–3 строки вывода:

- Что принято
- Почему
- Что делаем дальше

---

## Пример записи

```
## Шаг 1. Генерация вариантов концепта

> [!question] User 2026-02-15
> ```
> Роль: ты — геймдизайнер-редактор...
> Мои заметки: - жанр RPG... 
> ```

> [!todo] Answer with **GigaChat** 2026-02-15
>
> Вариант 1: "Подземелья и драконы"...
> Вариант 2: "Космическая станция"...

Выбрал варианты 1 и 3 как основу. Вариант 2 отклонил — слишком много контента.
```

---

## Шаблон для быстрой вставки в Obsidian

Создай в папке `Templates/` файл `llm-log-template.md`:

```markdown
> [!question] User {{date}}
> 
> ```
> 
> ```

> [!todo] Answer with **модель** {{date}}
>
> 
```

---

## Где создать шаблон

Шаблон необходимо создать по пути:

```
Utility/Templates/llm-log-template.md
```

Это позволит быстро вставлять готовые блоки в любой лог-файл через обсидиановские сниппеты.

---

## Рекомендации

1. **Записывай каждый запрос** — даже "плохие" ответы показывают процесс мышления
2. **Кратко фиксируй выводы** — 2–3 строки достаточно
3. **Указывай модель** — разные LLM дают разные результаты
4. **Датируй записи** — помогает отслеживать прогресс
5. **Не стирай черновики** — они показывают эволюцию решения

## Примеры промптов для занятия

### Запрос #1 — Генерация вариантов концепта (таблица 12–15)

```
Роль: ты — геймдизайнер-редактор. Помоги раскрыть МОЮ идею, не придумывай случайный жанр.

Мои заметки (не выдумывай за меня):
- [5–7 пунктов: жанр, настроение, платформа, что нравится, что нельзя]

Ограничения:
- Платформа: [PC/Mobile/Web]
- Масштаб: учебный проект на семестр (небольшой)
- Запреты: не копировать узнаваемые IP/бренды, не использовать реальных людей
- Тон/тема: [что нужно]

Критерии "хорошо":
- понятное короткое описание игры
- главный цикл игры в 1 строке (делает → получает → повторяет)
- игра помещается в масштаб семестра
- есть 1 "особенность" (что отличает)

Сгенерируй 12–15 вариантов в таблице:
1) Название (рабочее)
2) Жанр/вид
3) Роль игрока ("Я — …")
4) Особенность (1 фраза)
5) Главный цикл (1 строка)
6) Риски (1–2 пункта)

Лимит: до 20–25 слов в ячейке.
```

### Запрос #2 — Критика и улучшение топ-3

```
Ниже мои критерии и 3 выбранных варианта.
Задача:
1) Для каждого варианта: 1 сильная сторона + 1 слабое место.
2) Улучши каждый вариант так, чтобы слабое место стало меньше (сохрани мои ограничения).
3) Дай 5 уточняющих вопросов, чтобы я выбрал лучший.

Не придумывай новые варианты, работай только с моими тремя.
```

### Запрос #3 — Упаковка в GDD (короткое описание + цикл игры + механики)

```
Вот выбранный вариант (описание ниже).
Собери для GDD в Markdown:

## 1. Короткое описание игры
- 1 предложение
- 5 пунктов (жанр/роль игрока/особенность/цель/тон)

## 2. Главный цикл игры
- 4–7 шагов
- где прогресс
- почему игрок повторяет

## 3. Механики/элементы
- 5–8 пунктов
- раздели на "обязательно" и "если успеем"

Пиши коротко, без воды.
Описание варианта:
[вставь выбранный вариант]
```

### Запрос #4 — Главный цикл игры

```

1) 2 варианта главного цикла игры (по 4–7 шагов, в виде цикла)
2) Для каждого варианта: где награда/прогресс и почему игрок повторяет цикл
3) 3 риска (что может не работать) и быстрые смягчения

Описание концепта:
[вставь короткое описание игры]
```

### Запрос #5 — Механики и контент-план

```
На основе главного цикла игры ниже:
1) Предложи 8 механико/элементов. Для каждого отметь: Core (обязательно) или Optional (если успеем).
2) Сопоставь механику с шагом цикла (какой шаг поддерживает).
3) Составь контент-план: 20 пунктов (ассеты/тексты/UI), которые надо будет произвести для демонстрации концепта.

Главный цикл игры:
[вставь главный цикл]
```

3) 3 вопроса, на которые нужно ответить до начала разработки

Концепт:
